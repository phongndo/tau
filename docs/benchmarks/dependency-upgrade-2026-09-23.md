# Dependency compatibility and performance — 2026-09-23

Scope: all **direct** workspace dependencies and the daemon's Zig dependencies on NixOS x86_64. Policy: latest compatible stable releases, continuing Effect's existing prerelease track; no nightly/dev snapshots. This is a point-in-time assessment, not a claim that future registry releases remain compatible. Sources: npm registry package metadata (`https://registry.npmjs.org/<package>`; for scoped packages substitute the URL-encoded name), [Electron Vite 5 peer requirements](https://github.com/alex8088/electron-vite/blob/v5.0.0/package.json), [Ghostty v1.3.1 Zig requirement](https://github.com/ghostty-org/ghostty/blob/v1.3.1/build.zig.zon), [zig-sqlite version support](https://github.com/vrischmann/zig-sqlite/blob/29c0e65a80b38203c010ed31e7a72d2f804649a5/README.md), and [Zig releases](https://ziglang.org/download/). Versions were checked against these primary sources on the date above; `bun.lock` records the resolved transitive graph.

The root and desktop manifests now declare the same Electron version. The installer and package smoke both resolve the desktop workspace's Electron binary (not an unrelated root copy); the installer fails on a root/desktop version mismatch. For editors, TypeScript 7's bundled `tsc --lsp --stdio` replaces the separate TypeScript 5-based language server in the dev shell. Configure that command explicitly: a separately installed global legacy server might still be on the host's PATH. An LSP initialize request identified `typescript-go` 7.0.2, and a diagnostic request on an invalid assignment returned TS2322.

Bun's frozen install, lint, format (TS/Zig/Nix), TypeScript checks, persistence/tooling tests, Zig tests, production build, daemon check, packaged Electron launch, and xterm addon smoke passed on this machine. Electron launch and addon checks ran under Xvfb; a real GPU or macOS/Windows matrix was **not** available here. CI is configured for macOS/Linux/Windows builds but was not run remotely. The Electron smoke produced a GLib settings warning on the headless host, without failing.

Baseline repairs applied before the comparison: corrected the Zig package fingerprint's name hash (keeping its existing random suffix) and propagated `-Dstrip` to the executable module. The original ReleaseFast build otherwise failed in the Zig compiler with `local variable requires a valid scope`. The original Nix shell also omitted `unzip`, required by Electron's downloader; it is now supplied by the shell. Neither daemon source nor Ghostty version changed during the measured comparison.

## Performance before / after

Host: NixOS Linux x86_64, AMD Ryzen 9 9950X (32 logical CPUs), same checkout base `3b98e0f`. Baseline `bun.lock` SHA-256 `de9a209ec66424e5dea93ac1510c5eb1342081c86e0739078fc2ba747b625b4c`; measured-after `bun.lock` SHA-256 `cd9978622ac2521878087763c7e4a89e8d16f13a5390cb1c937515027bcfdd8d`. The later Electron alignment changed the final lockfile SHA-256 to `5e1097fa96ba7089f8e89d343ce46d04fc755dbc836259f5e9308f0778ffc2ad`; the daemon and parser measurements predate that alignment, but the tested daemon binary and xterm version did not change. Bun 1.4.2 and Zig 0.15.2 on both; Node 22.22.3 before, 24.15.0 after. Tests were sequential with warmed build/cache, not isolated from machine load. Numbers below are observed samples, not a regression guarantee.

Command for each daemon run: `TAUD_PATH="$PWD/apps/daemon/zig-out/bin/taud" TAU_LATENCY_BENCH_MANAGED_TAUD=1 TAU_LATENCY_BENCH_SAMPLES=200 bun run bench:latency` after `bun run build:taud` (baseline had no desktop `out/bin`, so the same daemon binary was selected without the explicit path). Each run spawns a new daemon and session under a temporary HOME; the benchmark reports rounded milliseconds per run. Raw individual request timings are not emitted by the existing harness.

| Run            | Before p50 / p95 / p99 / max (ms) | After p50 / p95 / p99 / max (ms) |
| -------------- | --------------------------------- | -------------------------------- |
| 1              | 0.03 / 0.06 / 0.17 / 0.77         | 0.03 / 0.05 / 0.10 / 1.00        |
| 2              | 0.04 / 0.05 / 0.13 / 1.13         | 0.04 / 0.05 / 0.09 / 0.96        |
| 3              | 0.04 / 0.07 / 0.24 / 0.96         | 0.04 / 0.06 / 0.09 / 0.93        |
| 4              | 0.04 / 0.06 / 0.12 / 0.88         | 0.04 / 0.07 / 0.20 / 0.96        |
| 5              | 0.04 / 0.07 / 0.21 / 1.14         | 0.04 / 0.06 / 0.10 / 1.04        |
| Median of runs | 0.04 / 0.06 / 0.17 / 0.96         | 0.04 / 0.06 / 0.10 / 0.96        |

**Observed difference:** no change in median p50, p95, or max; p99 median decreased by 0.07 ms. At this scale, that difference is not evidence of a causal improvement. The stripped, statically linked daemon is byte-identical before and after (SHA-256 `e978f760447ee737a9a89a4689355bc1ed43d94b62df72f79d04d375a3eef4df`, 2,584,320 bytes).

Secondary, single-run `bun run bench` parser outputs (Node.js, no rendering; xterm 6.0 unchanged; Ghostty-web is a separately fetched comparison package, **not** Tau's renderer):

| xterm JS parser workload | Before     | After      | Observed difference |
| ------------------------ | ---------- | ---------- | ------------------- |
| Plain 1 MiB              | 39.1 MB/s  | 46.4 MB/s  | +18.7%              |
| ANSI-heavy 1 MiB         | 26.2 MB/s  | 27.6 MB/s  | +5.3%               |
| Mixed 10 MiB             | 41.2 MB/s  | 40.7 MB/s  | −1.2%               |
| 1,000 tiny writes        | 1,319.5 ms | 1,334.0 ms | +1.1% time (slower) |

The parser harness printed its results but stayed alive until the outer timeout on both runs, so these are **partial-run observations**, not successful end-to-end benchmark exits. They also change Node versions, and one run per state cannot separate toolchain effects from ordinary variance. Do not extrapolate these numbers to frame time or key-to-display latency. Packaged Electron 44 smoke **after** alignment passed under Xvfb (16 KiB transfer); there is no comparable before-upgrade Electron sample, so no before/after startup claim.

For a controlled follow-up: use the same Node version in both trees, collect request-level raw samples and multiple parser runs, and run the Electron renderer and startup suites on a dedicated display/GPU. Benchmark commands and enforced smoke thresholds live in the root and desktop `package.json` files.
